# ArtLearn 后端系统设计文档

## 业务集合

### 1. 用户系统 (User)
**关联角色**: 普通用户、商家、学员

- **用户注册与登录**: 用户通过用户名和密码进行注册和登录，系统使用JWT进行身份认证
- **用户信息管理**: 用户可以查询、更新个人信息
- **批量用户查询**: 支持管理员批量查询用户信息

### 2. 艺术品商城系统 (Product/Order)
**关联角色**: 普通用户、商家

- **商品管理**: 商家可以发布、编辑、删除艺术品商品信息，支持单个和批量操作
- **商品浏览**: 用户可以查询商品详情，按分类浏览艺术品
- **购物车管理**: 用户可以添加、删除、修改购物车中的商品项
- **订单管理**: 用户可以创建订单、查询订单状态、修改订单信息、删除订单
- **批量订单查询**: 支持按用户ID批量查询订单

### 3. 艺术分类系统 (ArtCategory/ArtSubCategory)
**关联角色**: 商家、管理员

- **分类管理**: 管理艺术品的主分类和子分类
- **分类查询**: 用户可以按分类浏览和筛选艺术品

### 4. 在线课程系统 (Course/Chapter/CourseEnrollment)
**关联角色**: 学员、讲师

- **课程管理**: 讲师可以创建、编辑、删除课程，查询课程信息
- **章节管理**: 课程按章节组织内容，讲师可以管理章节
- **课程报名**: 学员可以报名参加课程
- **学习进度跟踪**: 学员完成章节后进行打卡，系统记录学习进度
- **我的课程**: 学员可以查询已报名的所有课程

### 5. 社区互动系统 (Post/Comment/Like)
**关联角色**: 普通用户、学员

- **帖子发布**: 用户可以发布艺术作品分享、学习心得等帖子
- **帖子管理**: 用户可以编辑、删除自己的帖子，查询帖子详情
- **评论功能**: 用户可以对帖子进行评论
- **点赞功能**: 用户可以对帖子、作品进行点赞和取消点赞

### 6. 收藏系统 (Collection)
**关联角色**: 普通用户、学员

- **收藏管理**: 用户可以收藏喜欢的艺术品、帖子等内容
- **收藏查询**: 用户可以查询和管理自己的收藏列表
- **批量收藏查询**: 支持批量查询收藏内容

### 7. 地址管理系统 (Address)
**关联角色**: 普通用户

- **收货地址管理**: 用户可以添加、编辑、删除收货地址
- **地址查询**: 用户可以查询自己的所有收货地址

### 8. 徽章系统 (Badge)
**关联角色**: 学员、普通用户

- **成就徽章**: 用户完成特定任务或达成里程碑后获得徽章
- **激励机制**: 通过徽章系统激励用户学习和参与社区活动

### 9. 讲师管理系统 (Instructor)
**关联角色**: 讲师、管理员

- **讲师信息管理**: 管理讲师的个人资料、教学经历等信息
- **讲师认证**: 讲师资质审核和认证

## 接口设计

### 1. 用户系统接口

#### 1.1 用户注册
- **接口**: `POST /user`
- **请求参数**: UserDTO (userName, password, email, phone等)
- **返回结果**: Result<User>
- **说明**: 创建新用户账户

#### 1.2 用户登录
- **接口**: `POST /user/login`
- **请求参数**: UserDTO (userName, password)
- **返回结果**: Result<String> (JWT Token)
- **说明**: 用户登录认证，返回JWT令牌

#### 1.3 查询用户信息
- **接口**: `GET /user?userId={userId}`
- **请求参数**: userId (Integer)
- **返回结果**: Result<User>
- **说明**: 查询指定用户的详细信息

#### 1.4 更新用户信息
- **接口**: `PUT /user`
- **请求参数**: UserDTO
- **返回结果**: Result<User>
- **说明**: 更新用户个人信息

#### 1.5 删除用户
- **接口**: `DELETE /user?userId={userId}`
- **请求参数**: userId (Integer)
- **返回结果**: void
- **说明**: 删除用户账户

#### 1.6 批量查询用户
- **接口**: `POST /user/batch`
- **请求参数**: List<Integer> (用户ID列表)
- **返回结果**: Result<List<User>>
- **说明**: 批量查询多个用户信息

## 其他服务需求分析

### 业务痛点

#### 1. 订单支付异步处理
**痛点**: 订单支付涉及第三方支付接口调用，响应时间不可控，同步处理会导致用户等待时间过长，影响用户体验。支付成功后需要更新订单状态、库存扣减、通知用户等多个操作。

#### 2. 课程学习进度统计
**痛点**: 需要实时统计用户的学习进度、完成率、学习时长等数据，频繁的数据库查询和计算会影响系统性能。

#### 3. 社区内容审核
**痛点**: 用户发布的帖子、评论等内容需要进行敏感词过滤和内容审核，同步处理会影响发布速度。

#### 4. 热门内容推荐
**痛点**: 需要根据用户行为（浏览、点赞、收藏、购买等）进行个性化内容推荐，实时计算推荐结果计算量大。

#### 5. 消息通知
**痛点**: 用户关注的课程更新、订单状态变化、评论回复等场景需要及时通知用户，但不能影响主业务流程的执行。

#### 6. 数据统计报表
**痛点**: 商家需要查看商品销售统计、课程学习统计、用户活跃度等报表，大量的聚合查询会影响数据库性能。

#### 7. 文件上传和存储
**痛点**: 用户上传艺术品图片、课程视频等大文件，需要考虑存储空间、访问速度和CDN加速。

#### 8. 实时互动通信
**痛点**: 课程直播、在线答疑等场景需要实时双向通信能力。

### 解决方案

#### 1. 消息队列系统
**技术选型**: RabbitMQ 或 Apache Kafka

**应用场景**:
- **订单异步处理**: 订单创建后发送消息到队列，消费者异步处理支付、库存扣减、发送通知等操作
- **内容审核队列**: 用户发布内容后立即返回成功，内容异步进行审核处理
- **消息通知队列**: 各类系统通知通过消息队列异步发送，避免阻塞主流程

**实施建议**: 
- 使用RabbitMQ的死信队列处理失败消息
- 设置消息重试机制和补偿机制
- 关键业务消息持久化保证不丢失

#### 2. 缓存系统
**技术选型**: Redis

**应用场景**:
- **热门内容缓存**: 缓存热门商品、课程、帖子信息，减少数据库查询
- **用户会话缓存**: 缓存JWT token和用户基本信息
- **学习进度缓存**: 缓存用户学习进度数据，定期持久化到数据库
- **点赞数、浏览数缓存**: 使用Redis计数器实时更新，定期同步到数据库

**实施建议**:
- 设置合理的缓存过期时间
- 使用缓存预热和缓存穿透保护
- 热点数据使用Redis集群保证高可用

#### 3. 对象存储服务
**技术选型**: MinIO (私有部署) 或 阿里云OSS / 腾讯云COS

**应用场景**:
- 存储用户上传的艺术品图片
- 存储课程视频、课件等教学资源
- 用户头像、帖子配图等静态资源

**实施建议**:
- 配置CDN加速，提升访问速度
- 设置图片压缩和格式转换
- 实施访问权限控制，保护付费内容

#### 4. WebSocket服务
**技术选型**: Spring WebSocket

**应用场景**:
- 课程直播功能
- 实时消息通知推送
- 在线客服和答疑

**实施建议**:
- 已集成WebSocket支持，可直接使用
- 考虑使用STOMP协议进行消息路由
- 实施心跳检测和断线重连机制

#### 5. 任务调度系统
**技术选型**: Spring Task 或 XXL-Job

**应用场景**:
- 定时统计数据报表
- 定时清理过期数据
- 定时发送课程提醒
- 定时同步缓存数据到数据库

**实施建议**:
- 使用XXL-Job实现分布式任务调度
- 设置任务执行日志和监控
- 实施任务失败重试和告警机制

#### 6. 搜索引擎
**技术选型**: Elasticsearch

**应用场景**:
- 商品全文搜索
- 课程内容搜索
- 帖子内容搜索
- 多条件筛选和聚合查询

**实施建议**:
- 使用IK分词器支持中文分词
- 数据库与ES数据同步策略
- 搜索结果高亮和相关度排序

#### 7. 数据库优化
**技术选型**: MySQL主从复制 + 读写分离

**应用场景**:
- 主库处理写操作
- 从库处理读操作
- 减轻单一数据库压力

**实施建议**:
- 配置MySQL主从同步
- 使用ShardingSphere实现读写分离
- 对热点数据添加索引优化查询
- 分表策略应对大数据量（如订单表）

#### 8. API限流和防护
**技术选型**: Spring Cloud Gateway + Redis

**应用场景**:
- 接口限流防止恶意刷单
- 防止爬虫抓取数据
- 保护系统稳定性

**实施建议**:
- 使用令牌桶或漏桶算法限流
- 针对不同接口设置不同限流策略
- 实施IP黑白名单机制

#### 9. 日志监控系统
**技术选型**: ELK Stack (Elasticsearch + Logstash + Kibana)

**应用场景**:
- 收集应用日志
- 错误日志分析
- 用户行为分析
- 系统性能监控

**实施建议**:
- 统一日志格式
- 设置日志级别和采样率
- 配置告警规则
